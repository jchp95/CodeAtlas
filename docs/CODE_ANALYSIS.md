# Análisis estático Roslyn (Fase 2)

Comando: `CodeAtlas.Engine analyze <repositorio> [--no-cache] [--rules ATL1001,ATL1003] [--max-parallelism N]`
Catálogo: `CodeAtlas.Engine analysis-rules` · Corrección: `CodeAtlas.Engine fix <repositorio> <id> [--apply [--base-hash HASH]]`
Prueba: `./scripts/code-analysis-test.sh` (incluida en `verify-before-launch.sh`).

El análisis **no ejecuta código del usuario ni MSBuild** y reutiliza la misma compilación que el escaneo de arquitectura (`RepositoryScanner.LoadDotnetProject`), por lo que ambas vistas se basan en el mismo modelo semántico.

## Modelo de hallazgo (`Features/Findings`)

Cada `Finding` incluye id estable, regla, categoría, severidad, **nivel de validación**, origen, ubicación (archivo, línea, columna, símbolo, proyecto), evidencias, ruta de llamadas (opcional), confianza, limitaciones, impacto, recomendación, **pasos de reproducción**, corrección opcional, estado e historial.

Niveles de validación (`ValidationLevel`), de menor a mayor evidencia: `hypothesis` < `staticRisk` < `staticProven` < `runtimeObserved` < `measured` < `reproduced` < `fixProposed` < `fixValidated`. Las reglas actuales solo emiten `staticProven` (el patrón existe y está resuelto por el modelo semántico; sus consecuencias pueden ser condicionales y así se dice en `impact`/`limitations`) y `staticRisk` (inferencia sobre la forma del código). Nada se marca como medido ni reproducido sin una ejecución real.

El **id** se calcula con regla + proyecto + archivo + símbolo + código ofensor normalizado + ordinal; no incluye números de línea, de modo que desplazar código no cambia la identidad (verificado por la prueba). `FindingMerger` fusiona hallazgos con el mismo id conservando todas las evidencias y el mayor nivel de validación.

## Reglas

| Id | Nombre | Validación | Qué demuestra y qué no |
|---|---|---|---|
| ATL0001 | SyntaxError | staticProven | Error de sintaxis del parser. No informa errores de referencias (CS0246…) porque no se restauran paquetes. |
| ATL1001 | BlockingOnAsync | staticProven | Existe `.Result`/`.Wait()`/`GetAwaiter().GetResult()` sobre un `Task`. Omite tareas ya esperadas con `await`/`WhenAll`. Interbloqueo o inanición **no** se miden. Severidad `warning` solo en miembros asíncronos. |
| ATL1002 | AsyncVoid | staticProven | `async void` que no tiene forma de manejador de evento. |
| ATL1003 | CancellationNotPropagated | staticProven | Hay un `CancellationToken` en alcance y se llama a un método con parámetro opcional o sobrecarga con token sin pasarlo. Incluye corrección automática. |
| ATL1004 | SwallowedException | staticProven (catch vacío) / staticRisk (catch amplio sin uso) | No marca todos los `catch`: ignora los que lanzan, llaman a algo o usan la excepción. |
| ATL1005 | ThrowResetsStackTrace | staticProven | `throw ex;` con la variable del `catch`. Incluye corrección automática. |
| ATL1006 | UndisposedResource | staticRisk | Local `IDisposable` creado con `new`, sin `Dispose`/`using` y que no escapa (return, argumento, asignación, captura). Escape intraprocedimental. |
| ATL1007 | RemoteCallInLoop | staticRisk | Llamada HTTP/BD resuelta (HttpClient, EF Core, ADO.NET, Dapper) por iteración. No demuestra N+1 sin proveedor, plan o comandos medidos. |
| ATL1008 | MultipleEnumeration | staticRisk | `IEnumerable`/`IQueryable` enumerado ≥2 veces o dentro de un bucle. Excluye ramas mutuamente excluyentes y secuencias reasignadas. |
| ATL1009 | CyclomaticComplexity | staticProven | Métrica exacta con las reglas de conteo indicadas en la evidencia; el umbral (15) es configurable. No es un defecto. |
| ATL1010 | MethodLength | staticProven | Líneas de código (sin blancos, comentarios ni llaves; umbral 80). "Responsabilidades mezcladas" se plantea como hipótesis, no como hecho. |

## Configuración

`codeatlas.analysis.json` en la raíz del repositorio (comentarios y comas finales permitidos):

```json
{ "exclude": ["**/Generated/**"],
  "rules": { "ATL1009": { "severity": "error", "threshold": 20 }, "ATL1010": { "enabled": false } } }
```
Exclusiones por defecto: `bin`, `obj`, `Migrations`, `*.g.cs`, `*.generated.cs`, `*.Designer.cs`, `AssemblyInfo` y archivos con `<auto-generated>`.

## Rendimiento del analizador

- Proyectos secuenciales (limita memoria), documentos en paralelo (`--max-parallelism`, por defecto = núcleos, máx. 16).
- **Caché por proyecto** con clave = versión del conjunto de reglas + configuración + `project.assets.json` + `.csproj` + hash de todos los fuentes. Cualquier cambio en el proyecto lo invalida: es la única granularidad segura, porque el resultado semántico de un documento depende de los demás. **No es incremental por documento.** Ubicación: `~/.config/CodeAtlas/analysis` (`CODEATLAS_CACHE_DIR` la sustituye).
- Se parsea y se crea la compilación antes de consultar la caché; la caché evita el enlace semántico y las reglas, no el análisis sintáctico.
- Cancelación cooperativa por `SIGINT`/`SIGTERM`: devuelve un informe parcial con `cancelled: true` y código de salida 130.
- Telemetría: tiempo total, de carga de compilación, por regla (ms y hallazgos), documentos, proyectos desde caché, paralelismo y memoria de trabajo al final (`Environment.WorkingSet`; no se afirma el pico porque macOS no lo expone).
- Medido en este equipo: 150 proyectos pequeños sin caché → ~10 s, ~116 MB.

## Correcciones automáticas

`fix` imprime siempre el diff unificado primero. Sin `--apply` no se modifica nada. Con `--apply` el motor exige que el archivo coincida byte a byte con el analizado (`baseFileHash`); si el llamador pasa `--base-hash` y no coincide, o el archivo cambió, **no se aplica** (código 5). Rechaza rutas fuera del repositorio.

## Limitaciones conocidas

- Sin `dotnet restore`, los símbolos de paquetes NuGet no resuelven; el informe lo advierte por proyecto y las reglas se abstienen en esas expresiones.
- Las reglas son intraprocedimentales; la propagación entre métodos llegará con el grafo de llamadas (Fase 3).
- No hay aún: nulabilidad/`NullReferenceException`, reflexión/`dynamic`, riesgos de concurrencia (locks, estado compartido), `IAsyncDisposable` en campos, complejidad cognitiva. Se registran como trabajo pendiente, no como cubiertos.
- La app SwiftUI aún no tiene vista de hallazgos (el build nativo no está disponible en este equipo); el contrato JSON está listo para consumirse.
